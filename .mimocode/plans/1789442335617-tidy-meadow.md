# Plan: Report Inventory PDF — company header (logo, name, address, tel)

## Goal

`/report-inventory` **PDF export** prints a normal company header:
- **App logo**
- **App name**
- **Address**
- **Telephone**

Match existing document-print chrome (same settings source as View/Print on receivings/adjustments).

## Current state

- `lib/print/document-print.ts` — `printDocumentPdf` already draws logo + name + address + phone via `loadLogoDataUrl` + `PrintAppSettings` (`appName`, `appLogo`, `address`, `phone`).
- That header is **inline** in `printDocumentPdf` (document form: doc no, fields, signatures) — **not** reusable yet.
- Report Inventory `exportPDF` is plain `jsPDF` + “Inventory Report” text only.
- Page passes only `timezone`; table has no `appSettings`.

## Approach

Extract **`drawCompanyHeader(doc, appSettings, opts)`** from `document-print.ts` and use it in Report Inventory PDF (not full `printDocumentPdf` — that is for single-document prints).

## Step-by-step

### Step 1 — Shared helper (`lib/print/document-print.ts`)

Export:

```ts
export interface PrintAppSettings { /* existing */ }

export async function drawCompanyHeader(
  doc: jsPDF,
  appSettings: PrintAppSettings | undefined,
  opts?: { rightTitle?: string; rightSub?: string; margin?: number }
): Promise<number>
```

Behavior (same as current document header):
1. `margin` default 14
2. If `appSettings?.appLogo`: `loadLogoDataUrl` → `doc.addImage(..., "PNG", margin, y, 14, 14)` (Cloudinary URL or `/uploads/...` already supported)
3. Text block next to logo:
   - **appName** bold ~14pt blue (`#337ab7`)
   - **address** ~9pt gray
   - **phone** prefixed `Tel:` or `T:` ~9pt gray
4. Optional right-aligned `rightTitle` / `rightSub` (e.g. Inventory Report + date period)
5. Blue rule under header
6. **Return Y** after the rule (caller uses as `autoTable` `startY`)

If `appSettings` missing: still draw `rightTitle`/rule; skip logo/name/address.

**Refactor:** `printDocumentPdf` header block should call `drawCompanyHeader` (or equivalent) so document PDFs stay the same — keep behavior, no visual regression on receivings/adjustments View print.

### Step 2 — Page (`app/(admin)/report-inventory/page.tsx`)

```ts
const appSettings = await getAppSettings();
// pass
appSettings={{
  appName: appSettings.appName,
  appLogo: appSettings.appLogo,
  address: appSettings.address,
  phone: appSettings.phone,
}}
```

Import `getAppSettings` from `@/lib/settings` (same as adjustments/conversions pages).

### Step 3 — Table (`report-inventory-table.tsx`)

1. Props:

```ts
interface ReportInventoryTableProps {
  timezone: string;
  appSettings?: {
    appName: string;
    appLogo: string | null;
    address: string | null;
    phone: string | null;
  };
}
```

2. `exportPDF` becomes **async**:
   - `new jsPDF({ orientation: "landscape" })`
   - `const startY = await drawCompanyHeader(doc, appSettings, { rightTitle: "Inventory Report", rightSub: period })`
   - `autoTable(doc, { startY, ...same columns/rows })`
   - `doc.save("report-inventory.pdf")`
   - Fallback title/period if header helper not used when settings empty

3. Import `drawCompanyHeader` from `@/lib/print/document-print`.

Excel export: **unchanged** (user asked PDF company header only).

2. `/report-inventory` → Generate → **PDF**
3. PDF header shows logo + app name + address + **Tel** + report title + period
4. Table starts below header; columns unchanged
5. Document View print (e.g. adjustments) still looks correct
6. Missing logo/address: PDF still generates; title/table still appear
