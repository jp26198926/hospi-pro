# Plan: Project-wide YYYY-MM-DD dates + DatePicker standard

**Rules (project-wide)**
1. **Display:** every user-facing date (tables, mobile, PDF/Excel, detail pages) is **`YYYY-MM-DD`**
2. **Input:** every date form/filter field uses **`components/ui/date-picker.tsx`** (calendar only, value `""` | `"YYYY-MM-DD"`) — never free-typed dates, never `type="date"`
3. **Docs:** README, AGENTS, MODULE_CREATION must state both rules

**Current state**
- `formatDateOnly` exists; stock-movements UI already uses it + DatePicker
- All other modules still call `formatDateTime` / `formatDateTimeLong` (time included)
- No other date inputs yet — DatePicker applies to future transaction forms and any date filters

---

## Step 1 — `lib/datetime.ts` (canonical behavior)

**File:** `lib/datetime.ts` (stay pure — no db/server imports)

- Keep **`formatDateOnly(date, timeZone)`** as the **canonical** formatter → `YYYY-MM-DD` via `Intl.DateTimeFormat("en-CA", { timeZone, year, month: "2-digit", day: "2-digit" })`
- Change **`formatDateTime`** and **`formatDateTimeLong`** to **delegate to `formatDateOnly`** so every existing call site immediately renders `YYYY-MM-DD` without missing a file:

```ts
/** Project-wide display format: YYYY-MM-DD */
export function formatDateOnly(...): string { /* en-CA */ }

/** Deprecated alias — use formatDateOnly. Outputs YYYY-MM-DD. */
export function formatDateTime(date: Date | string | number, timeZone: string): string {
  return formatDateOnly(date, timeZone);
}

/** Deprecated alias — use formatDateOnly. Outputs YYYY-MM-DD. */
export function formatDateTimeLong(date: Date | string | number, timeZone: string): string {
  return formatDateOnly(date, timeZone);
}
```

- Remove unused private `formatParts` **or** leave it unused until eslint/tsc complain — prefer **delete** if nothing else uses it
- JSDoc: project standard is **YYYY-MM-DD only** (app timezone via `getAppTimezone()`)

**Effect:** all detail pages, tables, exports, mobile cards across every module flip to `YYYY-MM-DD` in one step.

## Step 3 — DatePicker rule for date **fields**

**Existing component:** `components/ui/date-picker.tsx` (already done)

### Rule
| Context | Control |
|---|---|
| Date filter (Advanced Search) | `DatePicker` |
| Date form field (Add/Edit modals, future transactions) | `DatePicker` |
| Date **display** (table/detail/export) | `formatDateOnly` — not a picker |

### Current modules
- **Stock Movement** search: already DatePicker — no change
- Other modules: **no date inputs today** — no form changes required now

### New module / transaction modules (instruction)
- Any schema field like `date`, `dueDate`, `transactionDate` in forms/search **must** use:

```tsx
import { DatePicker } from "@/components/ui/date-picker";

<DatePicker
  id="date"
  value={date}
  onValueChange={setDate} // "" or "YYYY-MM-DD"
  placeholder="YYYY-MM-DD"
/>
```

- Do **not** use `type="date"` or free-text date inputs
- API: accept `YYYY-MM-DD`; convert to timestamptz at boundaries if needed (`T00:00:00.000Z` / end-of-day for inclusive To)

No code changes outside stock-movements for Step 3 beyond docs.
