# Plan: Full FEFO implementation (no phases)

## Goal

Implement **First Expiry, First Out** end-to-end in one delivery:

- Lot balances (`inventory_batches`) driven by receiving **batchNo + dateExpiry**
- **Complete receiving** creates lots; **cancel** reverses them
- **Complete releasing** allocates **FEFO** (earliest expiry first; null expiry last) + stores allocations
- **Cancel releasing** reverses the same lots
- **Transfers / adjustments / conversions** keep lot sums consistent with `stock_levels` / `products.stock`
- Scan remains **product-first**; Complete does auto-FEFO
- Optional manual batch pick on releasing line if straightforward; otherwise auto-FEFO only
- **Allowed:** truncate inventory stock/history records and reset balances so FEFO starts clean

**Defaults (locked unless you object at plan_exit):**

| Policy | Choice |
|--------|--------|
| Expiry on receive | Optional in UI; null expiry sorts **last** on FEFO |
| Negative lot qty | **Not allowed** — fail Complete |
| Manual batch override v1 | **Yes, optional** on releasing item (SearchableSelect of open lots); blank = auto FEFO |
| Truncate | Stock trail + balances + lots + inventory **document** rows (receivings/releasings/transfers/adjustments/conversions + items) + reset `products.stock` to 0; keep master data (products, locations, users, pages, trans types) |
| Dual totals | Keep updating `stock_levels` + `products.stock` **and** lots; invariant sum(batches) = stock_levels |

## Schema (`lib/db/schema.ts` + `db:push`)

### 1. New `inventory_batches`

```
id bigserial PK
productId FK products notNull
locationId FK locations notNull
batchNo text notNull
dateExpiry timestamptz null
qty decimal(10,4) notNull default 0
unitCost decimal(10,4) notNull default 0
sourceType text null          -- Receiving | Transfer | Adjustment | Conversion | Opening
sourceItemId bigint null
status commonStatusEnum default Active
createdAt/updatedAt/createdBy/updatedBy/deletedAt/deletedBy/deletedReason
unique (productId, locationId, batchNo)  -- use uniqueIndex; app excludes Deleted if soft-delete used
```

Index: `(productId, locationId, dateExpiry)` for FEFO.

### 2. New `releasing_item_batches` (allocation)

```
id bigserial PK
releasingItemId FK releasing_items notNull
releasingId FK releasings notNull
batchId FK inventory_batches notNull
qty decimal(10,4) notNull
dateExpiry snapshot null
batchNo snapshot text
createdAt defaultNow
```

### 3. New `transfer_item_batches` (optional but recommended for cancel)

Same shape as releasing_item_batches for transfer lines (from-side consumption).

### 4. Column adds

- `receiving_items.batchNo` text null
- `releasing_items.batchId` bigint null FK inventory_batches (manual pick; null = auto)
- `stock_movements.batchId` bigint null; `stockMovements.batchNo` text null (trail)

Then `npm run db:push`. If enum/column push fails, raw SQL `ALTER TABLE` as before.

## Core library changes

### `lib/receiving-stock.ts` — `completeReceiving`

For each draft item (same tx as today):

1. Resolve `batchNo = item.batchNo || \`BATCH-${String(item.id).padStart(6, "0")}\``
2. Upsert `inventory_batches` on `(productId, master.locationId, batchNo)`:
   - `qty += item.qty`
   - `dateExpiry = item.dateExpiry`
   - `unitCost = item.unitCost`
   - `sourceType = "Receiving"`, `sourceItemId = item.id`
3. Existing: movement (+qty, trans Receiving) **+ set** `batchId`, `batchNo` on movement
4. Existing: upsert `stock_levels`, update `products.stock` / costs

**Cancel receiving** (same file or API path): for each non-deleted completed item, find batch by `sourceItemId = item.id` **or** `(productId, locationId, batchNo)` and `qty -= item.qty`; movement reverse already exists — also stamp batch on reverse movement; fail if batch qty would go negative.

### `lib/releasing-stock.ts` — `completeReleasing` FEFO

Per draft item:

1. `need = qty`
2. If `item.batchId` set: only that batch (validate qty)
3. Else: select lots `productId`, `locationId = master.fromLocationId`, `qty > 0`, `status Active`, order:
   - `dateExpiry ASC NULLS LAST`, then `id ASC`
   - Use SQL `FOR UPDATE` / drizzle `for("update")` if available; else sequential updates in tx
4. Consume min(need, lot.qty); insert `releasing_item_batches` rows
5. Insert **one movement per take** with `batchId`/`batchNo` (better trace) OR one movement + batch in remarks — **prefer one movement per take**
6. After all takes for the line: update `stock_levels` / `products.stock` once by `-item.qty` (must equal sum takes)
7. If total lots < need → throw `Insufficient FEFO stock for product ...`

**Cancel releasing:** load `releasing_item_batches` for the document; for each allocation `batch.qty += alloc.qty`; reverse movements (existing); fail if batch missing.

### `lib/transfer-stock.ts`

**Complete:**

- From side: FEFO consume at `fromLocationId` (same algorithm); write `transfer_item_batches`
- To side: upsert batch with **same** `batchNo` + `dateExpiry` at `toLocationId` (+qty)
- Movements: existing dual legs + batch fields
- Do **not** change `products.stock` (unchanged policy); lots + both `stock_levels` legs must stay consistent

**Cancel:** reverse from-side allocations; reverse to-side batch increases (same batchNo/expiry); existing movement reverse.

### `lib/adjustment-stock.ts`

**Save (Completed):**

- `qtyAdj > 0`: upsert lot — if form has optional batch/expiry use them; else `batchNo = ADJ-{adjustmentId}`, `dateExpiry` null
- `qtyAdj < 0`: FEFO consume abs(qty) at location (or single lot if we add optional batchId later — v1 auto FEFO)
- Movements + stock_levels + products.stock as today + batch on movements

**Cancel:** reverse the same lots (store allocation in movements’ batchId; reverse those batches). If cancel cannot find batch, reverse FEFO opposite (increase earliest empty?) — **prefer:** on save, always write movement.batchId; cancel uses those movements.

### `lib/conversion-stock.ts`

**Save:** FEFO consume `fromQty` on from-product lots; create/increase to-product lot `batchNo = CNV-{id}` or inherit first consumed batchNo + its min expiry (recommend **new lot** `CNV-{id}` with `dateExpiry` = earliest consumed expiry).

**Cancel:** reverse both legs using stored movement batchIds when possible.
