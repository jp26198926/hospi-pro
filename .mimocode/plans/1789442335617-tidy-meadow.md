# Plan: Date From/To on Advanced Search — stock-levels, adjustments, transfers, releasings, receivings

## Goal

Same **Date From** / **Date To** Advanced Search filters as `/conversions` (DatePicker, table wiring, API `gte`/`lte`).

**Skip:** `/stock-movements` — already complete (modal + table + API on `stockMovements.date`).

**Reference:** `conversion-search-modal.tsx`, `conversions-table.tsx`, `app/api/conversions/route.ts` (and stock-movements for the same pattern).

## Universal pattern (per module)

1. **Search modal**
   - Import `DatePicker` from `@/components/ui/date-picker`
   - State: `dateFrom`, `dateTo` (`""`)
   - Extend `onSearch` with trailing `dateFrom: string, dateTo: string`
   - UI: stock-movements grid after the last filter field **before Status** (or at end if no Status):

```tsx
<div className="grid grid-cols-1 gap-4 sm:grid-cols-2">
  <div className="space-y-2">
    <Label htmlFor="date-from" className="text-sm font-medium text-[#333]">Date From</Label>
    <DatePicker id="date-from" value={dateFrom} onValueChange={setDateFrom} placeholder="YYYY-MM-DD" />
  </div>
  <div className="space-y-2">
    <Label htmlFor="date-to" className="text-sm font-medium text-[#333]">Date To</Label>
    <DatePicker id="date-to" value={dateTo} onValueChange={setDateTo} placeholder="YYYY-MM-DD" />
  </div>
</div>
```

   - `handleSearch` / `handleClear`: pass and reset both dates (`""`)

2. **Table**
   - `dateFrom` / `dateTo` state
   - `if (dateFrom) params.set("dateFrom", dateFrom)` (same for `dateTo`)
   - Add to `useCallback` deps
   - `onSearch` handler sets both + `setPage(1)`

3. **API GET**
   - Parse `dateFrom` / `dateTo`
   - Import `gte`, `lte` if missing
   - Same block as conversions:

```ts
if (dateFrom) {
  const from = new Date(`${dateFrom}T00:00:00.000Z`);
  if (!Number.isNaN(from.getTime())) conditions.push(gte(<table>.<dateCol>, from));
}
if (dateTo) {
  const to = new Date(`${dateTo}T23:59:59.999Z`);
  if (!Number.isNaN(to.getTime())) conditions.push(lte(<table>.<dateCol>, to));
}
```

   Status/location/etc. filters stay; dates are AND.
