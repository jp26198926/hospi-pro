# Products form: Category + UOM on one row

## Goal

In the products **Add** / **Edit** modal only, put **Category** (left) and **UOM** (right) on the same row.

No API, schema, or validation changes.

## File

`components/products/product-form-modal.tsx` — only file to edit.

## Current layout (~L218–379)

1. Code  
2. Name  
3. **Category** — full-width standalone  
4. Brand | Model  
5. Min Stock | Stock | Last Cost | Avg Cost  
6. Selling Price (alone in a 4-col grid)  
7. **GST Type | UOM** — 2-col grid  

## Target layout

1. Code  
2. Name  
3. **Category (left) | UOM (right)** — `grid grid-cols-1 gap-4 sm:grid-cols-2`  
   - Category: optional, `allOption` / “None”, no error text (unchanged behavior)  
   - UOM: required `*`, `SearchableSelect`, `errors.uomId`  
4. Brand | Model  
5. Min Stock | Stock | Last Cost | Avg Cost  
6. Selling Price | **GST Type** — 2-col row so GST Type is not left half-empty alone  
   - Selling Price left, GST Type right (required `*`)  

Mobile: stacks to one column via `grid-cols-1` then `sm:grid-cols-2` (same as Brand/Model).

## Implementation steps

1. Replace the standalone Category `space-y-2` block (~L218–236) with a 2-col grid containing Category + the UOM Controller (move UOM up from the GST row).  
2. Change the GST Type | UOM grid (~L338+) so it is **Selling Price | GST Type** (or leave GST Type full-width alone if you prefer minimal move-only — **recommended: pair with Selling Price**).  
3. Keep all `register`/`Controller` names, options, and validation messages identical — layout only.

## Verification

1. Open Add Product: Category left, UOM right; both dropdowns work; UOM still required.  
2. Open Edit: both prefilled; save still works.  
3. Stacked order on narrow screens: Category then UOM.  
4. GST Type still required and visible.  
5. Optional: `npx tsc --noEmit` — expect no change-related errors.
