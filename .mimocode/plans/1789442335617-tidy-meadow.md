# Plan: Refresh Receiving Items table after Mark as Completed (and other master actions)

**Problem:** After **Mark as Completed**, master `refresh()` updates `/receivings/[id]` status, but `ReceivingItemsTable` only refetches when `receivingId` or `showCancelled` change — item **Status** stays **Draft** until a full reload.

**Goal:** On successful complete (and cancel/restore for consistency), items DataTable reloads so status becomes **Completed** (or Cancelled/Draft) immediately.

---

## Files

### 1. `components/receivings/receiving-detail-client.tsx`

After master `refresh()` succeeds, also bump a **items reload counter**:

```tsx
const [itemsReloadKey, setItemsReloadKey] = useState(0);

const refresh = async () => {
  try {
    const res = await fetch(`/api/receivings/${receiving.id}`);
    const json = await res.json();
    if (res.ok) setReceiving(json.data);
  } catch { /* ignore */ }
  setItemsReloadKey((k) => k + 1);
};
```

Pass to items table:

```tsx
<ReceivingItemsTable
  receivingId={receiving.id}
  masterStatus={receiving.status}
  timezone={timezone}
  onMutated={refresh}
  reloadKey={itemsReloadKey}
/>
```

`ReceivingActionModal` already uses `onSuccess={refresh}` — no change needed there once `refresh` increments the key.

### 2. `components/receiving-items/receiving-items-table.tsx`

- Add prop: `reloadKey?: number` (default `0`)
- Include it in the fetch effect so any parent-driven mutation reloads rows:

```tsx
useEffect(() => {
  fetchData();
}, [fetchData, reloadKey]);
```

- Optionally add `masterStatus` to `fetchData` `useCallback` deps as well (status prop change alone can trigger refetch).

Item form/delete/restore already call `fetchData()` + `onMutated()` — still correct; `onMutated` → `refresh` → key bump is harmless double refresh (or skip key bump if `onMutated` already refetched — prefer key-only for consistency).

**Recommended:** keep item modal path as-is (`fetchData` + `onMutated`); master path uses `reloadKey`. Both end with fresh data.
