# Fix: Advanced Search on /roles/[id] — ID vs name mismatch

## Root Cause

`components/role-permissions/role-permission-search-modal.tsx` sends page/permission **IDs** (from SearchableSelect options) as `searchPage` and `searchPermission` query params.

But `app/api/role-permissions/route.ts` lines 29–33 treat them as text for `ilike` name matching:

```ts
// Current (broken): searches page NAME containing the ID string
if (searchPage) {
  conditions.push(ilike(pages.page, `%${searchPage}%`));
}
if (searchPermission) {
  conditions.push(ilike(permissions.permission, `%${searchPermission}%`));
}
```

So selecting page "Roles" (id=1) sends `searchPage=1`, and the API searches for page names containing `"1"` — wrong results or none.

## Fix

**File**: `app/api/role-permissions/route.ts`

Replace the two `ilike` conditions with `eq` on IDs:

```ts
if (searchPage && searchPage !== "all") {
  conditions.push(eq(pages.id, parseInt(searchPage)));
}
if (searchPermission && searchPermission !== "all") {
  conditions.push(eq(permissions.id, parseInt(searchPermission)));
}
```

Add `eq` to the drizzle-orm import if not already there (it is — line 5 already imports `eq`).

No changes needed in the modal or table component — they already send IDs correctly.

3. Select a specific Page (e.g. "Roles") → Search → table filters to only that page's grants
4. Select a specific Permission (e.g. "Delete") → Search → filters correctly
