# Plan: Retrofit all app modals to pinned header/footer scroll shell

## Goal

Apply the **conversions modal standard** to every existing modal in the app:

- **DialogContent**: `showCloseButton={false}` + `flex max-h-[90vh] flex-col` + existing size (`sm:max-w-*`) + `rounded-sm border-[#ddd] p-0`
- **Scrollable region only**: `min-h-0 flex-1 overflow-y-auto` on the body (fields/content)
- **Header + footer**: stay pinned (siblings of the scroll area, not inside it)
- Do **not** change `components/ui/dialog.tsx`
- Skip **conversions** (already done)
- Leave **SearchableSelect** internal `max-h-48 overflow-y-auto` alone

Reference: `components/conversions/conversion-form-modal.tsx`, `conversion-search-modal.tsx`, `conversion-view-cancel-modals.tsx`.

## Patterns

### Pattern A — body div + footer sibling (~50 dialogs)

Search / delete / view / cancel / action / document master forms where structure is already:

```
header div
body div (space-y-4 p-4 | p-4 | grid …)
footer div (border-t …)
```

**Delta only (no restructure):**

1. DialogContent: add `showCloseButton={false}`; className → `flex max-h-[90vh] flex-col rounded-sm border-[#ddd] p-0 sm:max-w-{md|lg|x…}` (keep existing max-w).
2. Body div: prepend `min-h-0 flex-1 overflow-y-auto` to existing layout classes.

Examples:
- `…/department-search-modal.tsx` body L63 `space-y-4 p-4` → `min-h-0 flex-1 space-y-4 overflow-y-auto p-4`
- Adjustment View body grid → `min-h-0 flex-1 grid grid-cols-1 gap-3 overflow-y-auto p-4 sm:grid-cols-2`

**Special A:** `users/user-password-modal.tsx` — footer is **inside** the body div. Split like Pattern B: fields get scroll wrapper; footer stays sibling inside body’s flex column (or move footer out of body as a direct DialogContent child). Prefer: DialogContent flex shell; body = `flex min-h-0 flex-1 flex-col`; inner fields `min-h-0 flex-1 space-y-4 overflow-y-auto p-4`; keep footer div as last child of body with existing `border-t border-[#eee] pt-4`.

### Pattern B — `<form>` wraps fields + footer (~18 forms)

CRUD form modals: department/role/category/uom/gst-type/location/payment-method/payment-term/trans-type/permission/page/supplier/user/role-permission-add + auth profile/change-password.

**Before:** form `className="space-y-4 p-4"` contains fields + footer (`border-t border-[#eee] pt-4` or `DialogFooter`).

**After:**

```
<DialogContent showCloseButton={false}
  className="flex max-h-[90vh] flex-col rounded-sm border-[#ddd] p-0 sm:max-w-md">
  {header unchanged}
  <form onSubmit={…} className="flex min-h-0 flex-1 flex-col">
    <div className="min-h-0 flex-1 space-y-4 overflow-y-auto p-4">
      {/* existing field children only */}
    </div>
    {/* footer: Ace style preferred */}
    <div className="flex justify-end gap-2 border-t border-[#eee] bg-[#f8f8f8] px-4 py-3">
      …buttons…
    </div>
  </form>
</DialogContent>
```

- Keep submit handlers / RHF wiring unchanged.
- Auth modals may keep `DialogFooter` but place it **outside** the scroll wrapper as the last child of `<form>` (still pinned).
- Optionally normalize form footer chrome to Ace (`bg-[#f8f8f8] px-4 py-3`) where currently only `pt-4` — match conversion-form if easy; visual consistency is nice but not required for scroll behavior.

### Pattern C — products form wrong shell (1 file)

`components/products/product-form-modal.tsx` L167 currently scrolls the **whole** dialog (`max-h-[90vh] overflow-y-auto` on DialogContent).

Replace with Pattern B: DialogContent `flex max-h-[90vh] flex-col … sm:max-w-lg` (drop overflow-y-auto on DC); wrap fields in scroll div; pin footer inside form.

### Pattern D — settings loading spinners (4 files)

Consistency only (short content, no footer):

- `components/settings-application/settings-form.tsx`
- `components/settings-mail/settings-form.tsx`
- `components/settings-sms/settings-form.tsx`
- `components/settings-cloudinary/settings-form.tsx`

Add `flex max-h-[90vh] flex-col` to DialogContent (already `showCloseButton={false}`); body `flex min-h-0 flex-1 flex-col items-center gap-3 p-6`.
