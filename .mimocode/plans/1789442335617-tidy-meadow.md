# Plan: Receivings module (master-detail + inventory post)

Document workflow **Draft → Completed | Cancelled**. First transactional module that writes `stock_movements`, `stock_levels`, and `products` costs.

**User decisions**
- Create: **master form first**; items added on `/receivings/[id]`
- **Draft cancel**: mark Cancelled only — **no stock reverse** (stock never posted)
- **Completed cancel**: reverse stock **later** (API designed for it; UI only shows Cancel on Draft now)
- **Print**: document PDF (jsPDF) when Completed
- **Seed** trans types `Receiving` + `Receiving Cancel` if missing
- Layout: **same pattern as `/roles/[id]`** (left child table, right master info + actions)

**Note 2 correction:** second UI block is for status **Cancelled** (Restore only), not Completed.

---

## Status model (intentional deviation)

New enum — do **not** use `commonStatusEnum`:

```ts
export const receivingStatusEnum = pgEnum("receiving_status", [
  "Draft",
  "Completed",
  "Cancelled",
]);
```

| Master status | Meaning |
|---|---|
| Draft | Editable; items editable; Complete/Cancel available |
| Completed | Stock posted; read-only + Print |
| Cancelled | Restorable to Draft |

Child items share the same enum; stock posting uses **Draft** items on Complete.

**Permissions mapping** (no new permission names):
| Action | Permission |
|---|---|
| List/view pages | View + Read |
| Create master / edit draft / add-edit items | Add / Edit |
| Mark as Completed | Edit |
| Cancel | Delete |
| Restore | Restore |
| Print / exports | Export |

### Seed trans types
```sql
INSERT INTO trans_types (name, status)
SELECT v.name, 'Active'
FROM (VALUES ('Receiving'), ('Receiving Cancel')) AS v(name)
WHERE NOT EXISTS (
  SELECT 1 FROM trans_types t WHERE t.name = v.name AND t.status <> 'Deleted'
);
```

## Step 3 — API

### Helpers (inline or `lib/receivings.ts`)
- `formatReceivingNo(id)` → `RCV-${String(id).padStart(5, "0")}`
- `formatBatchNo(id)` → `BATCH-${String(id).padStart(6, "0")}`
- Resolve `transTypeId` by name (`Receiving` / `Receiving Cancel`)

### `app/api/receivings/route.ts`
**GET** list — `requirePermission(..., "/receivings", "Read")`
- Params: page, limit, search, sortBy (def `date`/`createdAt`), sortOrder, status (`all`|`Draft`|`Completed`|`Cancelled`), supplierId
- Join suppliers, users for `createdByEmail`
- Search: receiving id text, supplier name, po, invoice, remarks
- Map each row: `transNo: formatReceivingNo(id)`
- Response `{ data, total, page, limit }`

**POST** create master — `requirePermission(..., "/receivings", "Add")`
- Validate `receivingSchema`
- Insert `{ ...fields, status: "Draft", createdBy: auth.userId }`
- Return `{ data }` with `transNo`
- **No items in this request**

### `app/api/receivings/[id]/route.ts`
**GET** one — Read
- Join supplier/location names + createdBy email
- Include `transNo`, status, audit/cancel fields

**PUT** update master — Edit
- **Only if status === "Draft"** else 400 `"Only draft receivings can be edited"`
- Update date, supplier, location, po, invoice, remarks; `updatedAt`, `updatedBy`
- Items not in this handler

**DELETE** cancel — Delete
- Body optional `{ reason }`
- If **Draft**: set master + all **Draft** items → `Cancelled`, `cancelledAt/By/Reason`; **no stock**
- If **Completed** (enabled later): reverse stock in transaction (see Complete inverse); then mark Cancelled
- If already Cancelled → 400
- Message: `"Receiving cancelled successfully"`

**PATCH** restore — Restore
- Only if status === "Cancelled"
- Master → Draft; clear cancelled fields; `updatedBy`
- **Items**: restore all Cancelled items that were cancelled **with** this master to Draft (simple: all Cancelled items on this receiving); clear their cancelled fields
- **No stock** on restore from Draft-cancel path
- If cancelled-from-completed reverse is added later: restore Draft after reversing already done (or re-post — document: v1 restore only valid when cancel did not reverse stock)

### `app/api/receivings/[id]/complete/route.ts`
**POST** — Edit permission
- Load master; must be Draft with ≥1 Draft item (qty > 0 recommended; allow 0 with warning? **require qty > 0**)
- `db.transaction(async (tx) => {...})`:
  1. Select Draft items + product join
  2. For each item:
     - `transTypeId` = Receiving
     - Insert `stockMovements`: `date` = master.date, product, location = master.locationId, **qty = +item.qty**, `referenceTransId = master.id`, `referenceItemId = item.id`, `referenceDescription = formatReceivingNo(master.id) + "-" + formatBatchNo(item.id)`, `remarks` = item.remarks or master.remarks, `createdBy`
     - Upsert `stockLevels`: find by (productId, locationId); if exists `qty = qty + item.qty`, `updatedAt`, `updatedBy`; else insert `{ productId, locationId, qty, updatedBy }`
     - Update `products`: `stock = stock + qty`; `lastCost = unitCost`; `avgCost`:
       ```
       prevQty = product.stock
       prevAvg = product.avgCost
       newQty = prevQty + qty
       avg = newQty > 0 ? (prevQty * prevAvg + qty * unitCost) / newQty : unitCost
       ```
     - Item → `status: "Completed"`, `updatedAt`, `updatedBy`
  3. Master → `Completed`, `updatedAt`, `updatedBy`
- Return `{ data }`

### `app/api/receivings/[id]/cancel-completed/route.ts` (optional v1 stub)
Same as DELETE when status Completed; reverse postings:
- For each **Completed** item: stockMovements qty **negative**, trans type `Receiving Cancel`
- Decrement stock_levels and products.stock; recompute avgCost (document formula: reverse using last unit cost)
- Mark items + master Cancelled

**v1:** implement body in DELETE when Completed; UI still hides Cancel on Completed until product owner enables it.

### `app/api/receiving-items/route.ts`
**GET** list — Read
- Query `receivingId` (required), optional `showCancelled` (`true`|`false`)
- Default: items where status ≠ Cancelled **or** all if `showCancelled=true`
- Join products (code, name)
- Map: `batchNo: formatBatchNo(id)`, `totalCost`
- Search on product code/name/remarks optional

**POST** create item — Edit
- Body: `receivingId` + item fields
- Load parent; **only Draft**
- Compute `totalCost = qty * unitCost`
- Insert status Draft, `createdBy`

### `app/api/receiving-items/[id]/route.ts`
**GET** one optional
**PUT** — Edit; parent Draft + item Draft; recompute totalCost
**DELETE** cancel item — Delete; body `{ reason }`; item must be Draft; set Cancelled fields
**PATCH** restore item — Restore; Cancelled → Draft; parent must be Draft

### Receiving print
**`app/api/receivings/[id]/print-data/route.ts`** — Read  
Returns master + non-cancelled items + app settings (name, logo) for client jsPDF.

Or generate PDF entirely client-side from GET `/api/receivings/[id]` + items list (simpler v1).

**proxy.ts:** no public routes.

## Complete / Cancel logic summary

### Mark as Completed (transaction)
```
Draft master + Draft items
→ stock_movements +qty (trans: Receiving)
→ stock_levels upsert +qty (product + master.locationId)
→ products.stock += qty; lastCost = unitCost; avgCost = weighted average
→ items + master → Completed
```

### Cancel Draft
```
Master + Draft items → Cancelled
NO stock_movements / stock_levels / products changes
```

### Cancel Completed (later / API-ready)
```
Completed items
→ stock_movements -qty (trans: Receiving Cancel)
→ stock_levels -qty; products.stock -= qty; reverse avg/last as documented
→ master + items → Cancelled
```

### Restore
```
Cancelled → Draft (clear cancel audit)
v1: only intended when cancel did not reverse stock
```

## Gotchas

- New enum is **exception** to “always commonStatusEnum”
- First module using **`db.transaction`** + stock_levels **upsert** (`onConflictDoUpdate` or select+update)
- Trans # / batch # derived — not unique columns
- `dateExpiry` + `DatePicker`; display `formatDateOnly`
- Do not hard-delete receivings/items
- List API status filter uses Draft/Completed/Cancelled not Active/Deleted
- Badge colors: Draft orange, Completed green, Cancelled gray/red
- Sidebar icon `shopping-cart` already mapped
- Grant Read on suppliers/locations/products for dropdowns
- User note 2 = **Cancelled** status for Restore-only UI
