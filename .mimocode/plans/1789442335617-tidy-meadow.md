# Plan: Stock Movement Advanced Search — Date From / Date To

Small enhancement to `/stock-movements` Advanced Search modal + list API. No schema change.

**Behavior**
- Optional **Date From** and **Date To** (`type="date"`, HTML `YYYY-MM-DD`)
- Inclusive range on `stock_movements.date` (timestamptz)
- Empty From/To = no bound on that side
- Filters stack with existing: search term, trans type, location

## 1. API — `GET /api/stock-movements`

Read query params:
- `dateFrom` — optional `YYYY-MM-DD`
- `dateTo` — optional `YYYY-MM-DD`

Drizzle conditions (import `gte`, `lte`):

```ts
if (dateFrom) {
  const from = new Date(`${dateFrom}T00:00:00.000Z`);
  if (!Number.isNaN(from.getTime())) {
    conditions.push(gte(stockMovements.date, from));
  }
}
if (dateTo) {
  const to = new Date(`${dateTo}T23:59:59.999Z`);
  if (!Number.isNaN(to.getTime())) {
    conditions.push(lte(stockMovements.date, to));
  }
}
```

- Filter **`stockMovements.date`** (transaction date), not `createdAt`
- Invalid dates ignored
- Same `where` already applied to data + count queries

## Gotchas

- Use movement **`date`**, not `createdAt`
- Inclusive end-of-day via `T23:59:59.999` on the same calendar day (UTC interpretation of the date input)
- Empty strings must not become `Invalid Date` conditions
