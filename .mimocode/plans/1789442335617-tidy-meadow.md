# Plan: Payment Term module

Full CRUD module **Payment Term** — DB → validation → API → UI → sidebar. Copy the **Payment Method** module we just shipped (best reference); UOM/suppliers only as secondary UI/audit templates.

**User decisions**
- `name`: required, unique
- `termDays` / `term_days`: integer ≥ 0, **default 0**
- `status`: `commonStatusEnum`, default `Active`
- Detail page `/payment-terms/[id]` — yes
- Form field: **number input** (`valueAsNumber` / coerce)
- Audit fields — yes (same as payment methods)

## Step 1 — Schema + migration

**File:** `lib/db/schema.ts` — append after `paymentMethods`:

```ts
export const paymentTerms = pgTable("payment_terms", {
  id: bigserial("id", { mode: "number" }).primaryKey(),
  name: text("name").notNull().unique(),
  termDays: integer("term_days").notNull().default(0),
  status: commonStatusEnum("status").notNull().default("Active"),
  createdAt: timestamp("created_at", { withTimezone: true, mode: "date" }).defaultNow().notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true, mode: "date" }),
  deletedAt: timestamp("deleted_at", { withTimezone: true, mode: "date" }),
  createdBy: bigint("created_by", { mode: "number" }).references((): AnyPgColumn => users.id),
  updatedBy: bigint("updated_by", { mode: "number" }).references((): AnyPgColumn => users.id),
  deletedBy: bigint("deleted_by", { mode: "number" }).references((): AnyPgColumn => users.id),
  deletedReason: text("deleted_reason"),
});
```

- `integer` already imported in `schema.ts` (used by `pages.order`).
- Reuse `commonStatusEnum`.
- DB unique on `name` is global (includes soft-deleted); app checks use `ne(status, "Deleted")`.

## Step 2 — Validation

**File:** `lib/validations/payment-term.ts`

```ts
import { z } from "zod";

export const paymentTermSchema = z.object({
  name: z.string().trim().min(1, "Name is required").max(100),
  termDays: z.coerce
    .number({ invalid_type_error: "Term days must be a number" })
    .int("Term days must be a whole number")
    .min(0, "Term days must be 0 or greater")
    .default(0),
});

export const paymentTermUpdateSchema = z.object({
  name: z.string().trim().min(1, "Name is required").max(100),
  termDays: z.coerce
    .number({ invalid_type_error: "Term days must be a number" })
    .int("Term days must be a whole number")
    .min(0, "Term days must be 0 or greater")
    .default(0),
  status: z.enum(["Active", "Deleted"]).optional(),
});

export type PaymentTermInput = z.infer<typeof paymentTermSchema>;
export type PaymentTermUpdateInput = z.infer<typeof paymentTermUpdateSchema>;
```

- Form uses **create** schema; API PUT also uses create schema (project convention).
- Coerce handles form number inputs; `.default(0)` if omitted.
- If zod version complains about `invalid_type_error`, use the project’s zod error style from other files (check `product.ts` at implement time) — only message shape may differ.

## Step 3 — API list + create

**File:** `app/api/payment-terms/route.ts`

Template: `app/api/payment-methods/route.ts`.

**GET** — `requirePermission(request, "/payment-terms", "Read")`
- Params: `page`, `limit` (max 100), `search`, `sortBy` (def `createdAt`), `sortOrder` (def `desc`), `status` (`all`|`Active`|`Deleted`)
- Search: `ilike(paymentTerms.name, %search%)`
- Sort map: `name` | `termDays` | `status` | `updatedAt` | else `createdAt`
- `Promise.all` data + count → `{ data, total, page, limit }`

**POST** — `requirePermission(..., "/payment-terms", "Add")`
- `paymentTermSchema.safeParse` → 400
- Uniqueness: `and(eq(name, value), ne(status, "Deleted"))` → 409 `"Payment term name already exists"`
- Insert `{ name, termDays: parsed.data.termDays, createdBy: auth.userId }`
- `{ data }` status 201

## Step 4 — API single resource

**File:** `app/api/payment-terms/[id]/route.ts`

Template: `app/api/payment-methods/[id]/route.ts`. `await params`; invalid id → 400.

| Method | Permission | Behavior |
|---|---|---|
| GET | Read | Active by id; 404 if missing |
| PUT | Edit | Create schema; uniqueness name excluding self + Deleted → 409; set `name`, `termDays`, `updatedAt`, `updatedBy` |
| DELETE | Delete | Soft delete + optional `{ reason }` → `deletedBy` / `deletedReason` |
| PATCH | Restore | Only Deleted rows; clear delete audit fields; set `updatedBy` |

**proxy.ts**: no public routes.

## Gotchas

- Next 16: `params` is Promise
- Soft delete only; uniqueness excludes Deleted; PUT excludes self
- PUT uses **create** schema
- Toast from `sonner`
- Permission cache 30s (`lib/permissions.ts`) — new grants visible after TTL or invalidate
- Unique `name` + soft-delete: DB unique can still block reuse after soft-delete (same as other modules)
- `role_permissions` composite unique `(roleId, pageId, permissionId)` — insert carefully
- AGENTS.md auto BEGIN/END block — edit only outside it
- Number input empty → NaN; schema must reject with clear message; default 0 when blank if coerce/default allows
