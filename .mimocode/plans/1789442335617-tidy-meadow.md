# Plan: Fix `/pages` Advanced Search (filters not applied)

## Problem

On `/pages`, Advanced Search still shows all records after entering a search value.

## Root cause

**`searchParent=all` is always sent to the API.** `"all"` is truthy, so the table includes it. The API runs `parseInt("all")` → `NaN` and builds `eq(pages.parentId, NaN)`, which fails the GET. The table only updates data when `res.ok`, so it **keeps the previous unfiltered list**.

Search text wiring (`search` + `ilike` on `pages.page`) is fine — the broken parent condition prevents the filtered query from succeeding.

Working modules guard the sentinel: `if (x !== "all") params.set(...)`.

## Step-by-step fix

### Step 1 — Table query param (primary fix)

**File:** `components/pages/pages-table.tsx` (~line 84)

```tsx
// before
if (searchParent) params.set("searchParent", searchParent);

// after
if (searchParent && searchParent !== "all") {
  params.set("searchParent", searchParent);
}
```

Leave `"none"` (no parent) working — still sent when parent is `"none"`.

### Step 2 — Align table default with modal

**File:** `components/pages/pages-table.tsx` (~line 58)

Init `searchParent` state to `"all"` if it is not already, matching the modal default.

### Step 3 — API defense in depth

**File:** `app/api/pages/route.ts` (~lines 64–68)

```ts
if (searchParent === "none") {
  // existing none branch
} else if (searchParent && searchParent !== "all") {
  conditions.push(eq(pages.parentId, parseInt(searchParent)));
}
```

Skip invalid numbers if easy (`Number.isFinite`); optional.

### Step 4 — Surface API errors (optional UX)

**File:** `components/pages/pages-table.tsx` fetch handler

On `!res.ok`, `toast.error(json.error || "Failed to load pages")` so silent 500s do not look like “search ignored.” Import `toast` from `sonner` if missing.

### Step 5 — Typecheck + smoke test

1. `npx tsc --noEmit`
2. `/pages` → Advanced Search:
   - Enter a page name/path → list filters (not all rows)
   - Status All/Active/Deleted still works
   - Parent = All → no parent constraint; search still applies
   - Parent = specific parent → only children
   - Parent = none (if option exists) → only root pages
   - Clear → full list restored
